# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Ralts CMS: a Go HTTP API (`cmd/web`, `internal/`, `pkg/`) plus a Next.js UI (`ui/`) for machines, maintenance records, attachments, flags and notifications. PostgreSQL (pgx) for data, S3-compatible storage for attachments (LocalStack locally).

## Commands

Backend (repo root):

```bash
make dev                # create .env.development/.env.test from env.example, start dev+test Postgres and LocalStack
make migrate-up         # apply db/migrations to dev (5432) and test (5433) DBs; needs the `migrate` CLI
make run                # API on :8080 (APP_ENV=development)
make test               # APP_ENV=test go test ./...
make integration-test   # -tags=integration suite in internal/integration (Docker required)
make lint               # revive over cmd/ internal/ pkg/ (downloads bin/revive on first run)
make generate           # go generate ./... — regenerates gomock mocks
go vet ./...            # CI runs this too
make seed-dev           # sample machines + users
```

Single test: `APP_ENV=test go test ./internal/handlers -run 'TestFlagsHandlerTestSuite/TestListForMachine' -v` (most tests are testify suites, so filter as `Suite/Method`)

Repository tests (`internal/*/repository_test.go`) spin up Postgres via testcontainers (`internal/testutils`), so Docker must be running even for `make test`.

First admin: `APP_ENV=development go run cmd/cli/main.go -type admin -username <user> -password '<pw>'` (other CLI modes: see `docs/cli.md`).

UI (`cd ui`):

```bash
npm run dev             # :3000, talks to NEXT_PUBLIC_API_BASE_URL (default http://localhost:8080)
npm test                # Jest; single file: npx jest src/hooks/useMachine.test.tsx
npm run lint            # ESLint
npm run build
npm run test:e2e        # Playwright; single spec: npx playwright test e2e/flags-page.spec.ts
```

CI (`.github/workflows/ci.yml`) runs: go vet, revive, build, unit tests, integration tests; UI lint, build, Jest; Playwright in the `mcr.microsoft.com/playwright` image. The image tag must match the `@playwright/test` version in `ui/package.json`; bump both together.

## Backend architecture

- `cmd/web/main.go` → `deps.Initialise()` → `router.NewRouter(deps)`. `internal/deps` is the single composition root: it loads config from env (`.env.<APP_ENV>`), builds the pgx pool and S3 client, and wires every repository and service into one `*deps.Dependencies` struct.
- Handlers (`internal/handlers`) take `*deps.Dependencies` and reach repositories/services through it. There is no separate handler interface layer.
- Routing is **gorilla/mux**, not the Go 1.22 ServeMux (the `.cursor/rules` text says otherwise; follow the code). In `internal/router/router.go`, static segments such as `/machines/export/csv` and `/machines/flags/open-by-machine` must be registered **before** `/machines/{serial_number}` routes.
- Three route tiers: public (`/health`, login, register, refresh, logout), `/api/v1/` with `AuthenticationMiddleware` (JWT), `/api/v1/admin/` with auth + `AdminOnlyMiddleware`. Finer permissions (flag create = admin, flag resolve = admin or assignee, flags list scoped to assigned machines) are enforced inside handlers, not middleware. The authenticated user comes from `internal/context`.
- Domain packages (`machines`, `maintenance`, `users`, `flags`, `notifications`, `audit`, `refreshtokens`, `attachments`) each own a `Repository` interface + pgx implementation, and a `Service` where there is business logic. Flags create notifications; audit is an async buffered-channel service with retention cleanup, drained in `deps.Shutdown`.
- Auth uses short-lived access JWTs plus rotated refresh tokens stored in the DB (`pkg/auth`, `internal/refreshtokens`); see `docs/auth-refresh-tokens.md`. Flag/notification rules: `docs/notifications-and-flagging.md`.
- Migrations: numbered `db/migrations/0000NN_name.{up,down}.sql` (golang-migrate). Always add both files; testcontainers tests apply them automatically.

### Go conventions in this repo

- Mocks are **gomock** (`github.com/golang/mock`) generated by `//go:generate mockgen ...` lines next to the interface, output as `mock_*.go` in the same package. Regenerate with `make generate` after changing an interface; don't hand-edit mocks.
- Tests use testify (`assert`/`require`/`suite`) and live in external `_test` packages (e.g. `package machines_test`).
- revive enforces doc comments on exported identifiers; CI fails on lint.
- Wrap errors with `fmt.Errorf("context: %w", err)`; Postgres error mapping helpers are in `pkg/pgxutil`.

## UI architecture

- Next.js 16 App Router, React 19, Tailwind 4, `nuqs` for URL state. This Next.js version has breaking changes from older releases (APIs, conventions, file layout): read the relevant guide in `ui/node_modules/next/dist/docs/` before using unfamiliar Next APIs, and heed deprecation notices.
- This root file is the only CLAUDE.md. When an agent runs `next dev`, Next recreates `ui/AGENTS.md` and `ui/CLAUDE.md` if both are missing (`node_modules/next/dist/server/lib/generate-agent-files.js`). Delete them if they appear and never commit them.
- Data flow: `src/services/*Service.ts` (fetch clients, paths from `src/config/api.ts`) → `src/hooks/use*.ts` → pages in `src/app/`. `src/utils/api.ts` + `tokens.ts` handle the auth header and refresh-on-401; `AuthContext` holds the session (`ralts_token` / `ralts_user` in storage).
- Jest tests sit next to source (`*.test.ts(x)`); `e2e/` is excluded from Jest.
- Playwright specs run against `npm run start` and mock the API. Use `e2e/fixtures.ts` (`signInAs`, `ADMIN_USER`, `NON_ADMIN_USER`) and `e2e/factories.ts` (`fulfilJSON`, response bodies). Route on an exact `URL.pathname` predicate rather than a glob so sibling endpoints don't shadow each other.
- User-facing features get an entry at the top of `src/data/changelog.ts` (shown at `/changelog`). The optional top banner is driven by `NEXT_PUBLIC_ANNOUNCEMENT_UNTIL`.

## Other pieces

- `redirect-legacy/`: small Node server redirecting the old domain (`make legacy-redirect-dev`).
- `railway.toml` / `ui/railway.toml`: Railway deploys. `railway-cron.toml` + `Dockerfile.migrate` + `scripts/backup-to-r2.sh`: weekly Postgres/bucket backup to Cloudflare R2. Deployment notes are in `docs/*-deployment.md`.
